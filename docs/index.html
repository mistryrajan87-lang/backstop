How this has moved

CoinMarketCap's Real World Assets endpoints are all latest — there is no historical series for any of them, and issuer attribution in particular exists only in the live call. This series is not fetched from anywhere: it is what the scheduled run wrote down each morning. One point per day, taken from that day’s last run.

What the headline covers

Two different denominators, kept apart on purpose. The index above is built on value, and value exists only where a token reports a market cap. Counting tokens instead gives a different and much less flattering picture, and confusing the two is the easiest mistake to make with this catalogue.

What this measures, and what it does not

Issuer here means the name CoinMarketCap attributes a token to. Its issuer record carries a name, a website and a token roster — not custody, jurisdiction or a legal entity — so nothing on this page says who is liable for a token, only whose name is on it.

  • Not a safety check. Safe would mean reserves audited, the contract sound, redemption possible. CoinMarketCap supplies a name, a ticker and a market-cap field — no attestations, no custody, no redemption terms. Adding a concentration index to that does not add safety.
  • Not a map of who pays you back. That is a legal question — which entity, in which jurisdiction, under which document. The API's “issuer” is a label on a token. For a fund, the sponsor, the tokenisation agent and the fund vehicle are three different answers, and this data distinguishes none of them.
  • Not investment advice, and not a buy list. This is one vendor's catalogue: gold-heavy, missing the large treasury products, with almost half its tokens unpriced. It is not a portfolio view and should not be read as one.

Issuer concentration within each chain

No Real World Assets endpoint carries a chain. Each token does carry a crypto_id, so Backstop takes it across to /v2/cryptocurrency/info for the platform — the only route to this view. Each row is one share vector, not a market: how the tokenised value sitting on that chain divides between issuers, rather than the share the chain holds. It is not a market in any sense that would license a competition reading — the field is platform, it falls back to the token's own name when there is none, and several rows are venues rather than chains.

Is the asset quoted anywhere off-chain?

quotes/latest returns tradfi_markets beside tokens: the non-token venues quoting the asset, each with an exchange, a ticker and a market URL. These are exchange listings rather than the asset's primary market — a tokenised equity's entry points at a crypto exchange's stock product, not at the exchange the share itself trades on. Read it as is this asset quoted anywhere off-chain, then read the venue split beside it. A concentration index of 10,000 on that split is arithmetic rather than a finding: nearly every listing the API returns names the same venue, so there is nothing left for the index to measure. It is here for completeness, and it is not the issuer result.

    What stops a wrong number being published

    The page and the data behind it are rebuilt together every morning by a scheduled job. A run that cannot satisfy the following does not publish: the page, the archive and the repository are left exactly as the previous run left them.

    • Two independent price sources have to agree. CoinMarketCap prices each asset twice — once at asset level, and once as the sum of the tokens that represent it. The run compares them across every asset both of them price. Outside 0.85–1.15× it aborts and publishes nothing; inside that but outside 0.98–1.02× it publishes and records a warning against quoting the headline until someone knows why.
    • The rendered page is checked against the data it was built from. A headless browser loads the built page and re-derives the figures on it, and the wording around them, from the same snapshot. It runs before the commit step, so a page that disagrees with its own data never reaches the repository. It is not sufficient, and the commit history says so: four wrong statements have shipped past it, each one caught by reading the rendered page rather than by a check. What replaced them tests the class rather than the instance — the bound on small shares is fuzzed over twenty thousand values now, instead of three. The honest claim is that this catches drift, not that it catches everything.
    • The prose is generated, not typed. The headline sentence, the line beneath it, the no-JavaScript box and the README’s figures are written into the files by the run that writes the data, between markers in the source. The README was the exception: it was regenerated every run and the regeneration was never committed, so the one file whose job is to quote current figures to someone who never opens the page sat two runs behind it. That is fixed, and the fix is in the history.
    • Every run is kept. One snapshot file per run, under its own timestamp, never overwritten. The daily series above is read from a separate one-row-per-day file; the per-run snapshots are the receipts behind it.
    • Calls the API refused are reported, not dropped. They are listed in the method section below. The one endpoint this plan cannot reach is recorded from the live refusal rather than assumed from the documentation.
    • The API key is not in the repository. It is an encrypted repository secret, read from the environment and sent as a request header. It is never written to a file, never placed in a URL, and never echoed — the run prints how many characters it is and nothing else.

    Read them yourself: the workflow holds the gates and their order, tests/ holds the checks, and Actions holds the log of every run, passed or refused.
